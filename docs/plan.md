# 计划：从截图识别工具到记账系统

状态：第 1 步已完成（2026-11-06）。上一版计划（数据库、核对入库、导出记录、登录）已全部完成，部署暂缓，挪到本计划最后一步。

## 目标

只有我一个人用的记账系统，部署在云端。

- **记一笔**是首页，有几种添加方式：
  - 截图识别：现在的流程（上传 → 待核对 → 提交入库）
  - 手动输入：自己填一笔或几笔
  - 邮件导入：自动读取账单 / 消费通知邮件（另一个项目里已经做好，需要整合进来）
- **统计**：每月按「种类 × 币种」加总支出和收入，再按汇率折算成本位币（人民币）合计
- 交易列表、导出 CSV、登录记录保留

## 统计表的样子（参照 `docs/example.csv`）

一个月一张表（每行一个种类，每列一个币种，适合做成网页表格）：

|  | 人民币 | 美元 | 日元 | 合计（折算成人民币） |
|---|---|---|---|---|
| 饮食费 | 该月人民币交易里这个种类的合计 | 同左（美元） | 同左（日元） | 各币种 × 当月汇率后相加 |
| 房租 | … | | | |
| … | | | | |
| **本位币合计** | 这一列的合计（人民币） | 这一列的合计（美元） | 这一列的合计（日元） | 全部折算后的总计 |
| **汇差盈亏** | — | 手填？ | 手填？ | — |
| **人民币合计** | 同本位币合计 | 折算后 + 汇差 | 折算后 + 汇差 | — |
| **人民币总计** | 各币种「人民币合计」相加 | | | |

我对示例数字的验算：

- 「合计」列 = 人民币 + 日元 × 当月汇率（示例里一个月只用一个汇率，例如 1 日元 = 0.042598 人民币，各种类都一致）
- 「本位币合计」行：各币种列是该币种自己的合计（还没折算）；「合计」列是全部折算成人民币的总数
- 外币列的「人民币合计」= 该列合计 × 汇率 + 汇差盈亏；最后一行是所有币种「人民币合计」相加
- 收入（如利息、红包）为正，支出为负，和交易里的正负号一致

## 数据模型的变化

- **transactions** 不再必须来自截图：`ocr_row_id` 改为可空，新增 `origin`（`screenshot` / `manual` / `email`）。旧库启动时自动重建这张表（已完成）
- **categories**：种类清单（名称、排列顺序、收入 / 支出 / 两者、是否停用）。统计表的列按这个顺序。现有交易里出现过的种类自动导入
- **accounts** / **currencies** / **account_currencies**（已建）：账户、币种清单，一个账户可以用多个币种（如现金既有日元也有人民币）。启动时从已有交易自动导入；截图识别入库时自动登记；手动输入遇到新的账户 / 币种 / 账户的新币种，会在确认框里问过再新增。以后在设置页加排列顺序、改名，币种标出本位币（人民币）
- **fx_rates**：月汇率（月份、币种、折算成本位币的汇率）
- **fx_adjustments**（待定）：每月每个币种的汇差盈亏
- 交易里的 `account` / `currency` / `category` 先继续存文字（导出 CSV 格式不变）。种类改名时，把已有交易一起改掉

## 页面

- **记一笔**（首页，已完成）：上面切换添加方式
  - 截图识别：和现在一样
  - 手动输入：日期时间、账户、币种（跟随账户）、金额（支出 / 收入切换）、种类（下拉）、描述；可以一次填多行再提交。默认直接入库，不经过待核对

- **设置**：种类、账户、币种与本位币、月汇率
- **登录记录**：和现在一样

## 第 1 步实现时补充的细节

- 「记一笔」页顶部三个标签：截图识别 / 手动输入 / 邮件导入（占位），记住上次用的。旧的 `#recognize` 链接会打开截图识别
- 手动输入是一张可以连续填的表，时间精确到秒；日期时间、账户、币种、金额、种类必填，描述可空；新行沿用上一行的日期、账户、币种、种类；回车到下一行，最后一行回车再加一行；金额填正数，用「收支」按钮切换（或在金额前加 + / -）；选了用过的账户会自动带出它上次的币种
- 账户、币种的输入框从清单里提示，币种优先列出这个账户用过的；选了账户后，如果当前币种不是它用过的，换成它最常用的那个。种类先用「用过的值」提示（`/api/suggestions`）
- 点「入库」先弹出确认框：列出要入库的每一笔、按币种的支出 / 收入合计，以及将要新增的账户 / 币种；默认焦点在「返回修改」，避免误按回车。服务器那边没有 `add_accounts` 就拒绝新账户 / 新币种（409）
- 没入库的手动输入暂存在浏览器 localStorage 里，刷新不丢
- 交易页「添加方式」筛选：全部 / 手动输入 / 各截图来源。手动输入的交易入库后和截图识别的一样：只能改种类和描述，不能删除，也不做特殊显示（只是点了没有截图可看）
- 还没做：手动输入的交易和之后上传截图识别出的同一笔交易之间不会互相比对，可能重复入库。以后看需要再加

## 现有设计（第一版，继续沿用）

- 截图按 SHA-256 判断是否传过，存成 WebP；传过的直接用 `images.parsed` 里的结果，换了来源会重新识别
- 识别出的行存 `ocr_rows`，原始值不改，比对只用它们；待核对时的修改存在 `draft`。比对规则：完全一致且已入库 → 跳过；完全一致且待核对 → 合并；日期金额一致、商户不同 → 疑似重复（`suspect_of`，默认不勾选）；其他 → 新行。不同来源之间不比；日期是推测的行只比看得到的部分
- 没有「忽略」状态，不要的待核对行直接删除
- 导出：每次导出记一条，`export_items` 记导出了哪些交易，允许重复导出
- 登录：单用户密码，哈希放在 `.env` 的 `TXREADER_PASSWORD_HASH`（`python -m txreader.auth` 生成）；连续 5 次密码错误且都在 15 分钟内就锁定 15 分钟；会话 2 小时不操作过期（`TXREADER_IDLE_MINUTES`），最长 30 天；cookie 为 HttpOnly + SameSite=Lax，HTTPS 下加 Secure
