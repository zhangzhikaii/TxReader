## 核算规则（结余、收支、汇差）

所有数字都从三样东西算出来：**交易**、**期初余额**、**月汇率**。结余、汇差都是算出来的，不存。

- **结余**（账户 × 币种 × 月底）= 上月底结余 + 本月交易合计；最早一个月从期初余额开始
- **期初余额**：设一个起始月，填每个账户、每个币种在那个月底的余额；起始月当月和之前的交易不影响结余，也不算进任何一个月的收支（2026-11-07）
- **月汇率**：每月每个外币一个，1 外币 = 多少本位币。原来是手填、不联网（2026-11-07）；改成有代码的币种从 Yahoo Finance 自动取，过去的月份取**月底最后一个交易日的收盘价**（和「月底结余 × 月汇率」一致），本月取最新价、月份结束后定成收盘价；手填的不覆盖，清空即改回自动；只在打开月汇率标签、结余页、收支页或点「更新汇率」时取（2026-11-13）。本位币固定为人民币、不能改（改了已填的汇率全都要重填，2026-11-07）
- **本位币收支**（币种 × 月）= 这个币种本月所有交易的合计 × 本月汇率
- **汇差盈亏**（币种 × 月）= **上月底**存量（所有账户合计）×（本月汇率 − 上月汇率）。最初说的是月底存量，验算后改成上月底才严格对上（2026-11-07）
- 两张表必须对上，页面上显示核对结果：对每个币种，收支 × 本月汇率 + 汇差 = 本月底结余 × 本月汇率 − 上月底结余 × 上月汇率；所以收支表的人民币总计 = 结余表的月度差额
- 结余和实际对不上时，由我自己记一笔「投资盈亏」/「余额调整」，系统不做对账功能（2026-11-07）
- 转账 / 换汇：A 账户一笔支出、B 账户一笔收入，时间相同，种类「内部转账」；不加专门的转账模式（2026-11-07）。每月对比里不列「内部转账」，月度收支表照示例算进合计（见 `plan.md` 待确认 1）
- 汇率、汇差、勾稽都按月算，所以收支页只有「月 / 年」，不做「日 / 周」（2026-11-10）

## 交易与入库

- 金额支出为负、收入为正；推出来的正负号 / 年份标 ⚠ 让我核对
- 手动输入直接入库，入库前弹确认框；遇到新的账户 / 币种 / 种类要在确认框里同意
- 入库后的交易（不论怎么添加的）只能改种类和描述，不能删除
- 没有「忽略」状态，不要的待核对行直接删除
- 识别的原始值（`ocr_rows`）不改，比对只用它们；修改存在 `draft`
- 去重只去不同截图之间的重复；同一张截图里两笔一样的都保留。不同来源之间不比
- 不记录导出：交易页按当前筛选条件导出 CSV，导出页去掉了（2026-11-09）
- 已知没做：手动输入的交易和之后截图识别出的同一笔不会互相比对，可能重复入库。以后看需要再加

## 清单（账户 / 币种 / 种类）

- 交易里存名称文字（导出 CSV 格式不变）；改名时把已有交易一起改，不能改成已有的名字（不做合并）
- 有地方在用的不能删除（交易、本位币、期初余额、汇率、持仓、邮件规则、待核对行），设置页显示原因
- 不做「停用」：既不拦输入、也不影响统计，没有用处（2026-11-07）
- 币种有 ISO 代码（`currencies.code`），添加时按名称猜，可以改，不能重复；取汇率、持仓认证券的币种都用它，不再按名称猜（2026-11-13）。改代码会删掉用旧代码取到的汇率重新取；只有手填的汇率挡着删除币种
- 账户类型是固定的几种（活期 / 定期 / 投资 / 信用卡 / 其他），不能自己加；只影响结余页的分组，不影响收支、汇差和核对（2026-11-12）
- 每月对比默认显示的种类在设置里标「固定」。经过：自动判断 → 写死四个 → 改成在设置里标记（2026-11-09）

## 设置页与编辑

- 防误触：默认只读，点「✎ 修改」后改动先暂存，「保存」列出改动确认后一起保存，有一处不行就一处也不改；不做「离开输入框就保存」（2026-11-09）。拖动排序不上锁。交易页、持仓页也这样

## 持仓

- 按天记，不是每周一份（2026-11-14；原来是每周一份，2026-11-12）：持仓只在变动时填，从那天起一直有效到下一次变动；看的是单个投资账户每天的市值和盈亏（总资产的每日曲线以后再说）；只是看看，不记成交易，结余页的数字不变
- 每次记完整的一张表，不记成交流水（买入 100 股）：和原来的用法一样，填错了下一份就纠正了
- 成本 = 结余页这个账户在那天结束时的余额；另有按成本价算的「持仓盈亏」
- 价格用 Yahoo Finance（非官方、不用 key），只发代码，不发数量、金额（2026-11-13）；每天的收盘价按代码存一份，证券和汇率共用（2026-11-14）
- 有行情代码的证券一律自动取价，不再能手改某一天的价格；要手填就去掉代码（2026-11-14）
- 每天的汇率只用在持仓上；有代码的币种从 Yahoo Finance 取，没有的用月汇率。结余页、收支页仍然只用月汇率（核对要对得上）；月汇率本来就是月底最后一个交易日的收盘价，所以月底那天两者一致
- 只在打开持仓页、点「更新价格」或查找时联网，没有后台定时任务

## 邮件导入

- 用 Microsoft Graph 读 Outlook，只要 `Mail.Read` + `offline_access`；只在点「从邮件更新」时读，从上次读到的时间往后读（2026-11-08）
- Client ID / secret、令牌、规则都存在数据库里，在「设置 › 邮件」录入，不放 `.env`（2026-11-08）
- 认出来的交易和截图一样先进待核对；读过的邮件都存在 `emails`，按 message_id 不再重复添加，删掉的待核对行也不会回来
- 规则里金额一律记为支出；币种由规则定，不从邮件里取（2026-11-08）

## 代码

- 不换前端框架：要引入构建步骤，不划算（2026-11-08）
- 金额不改成整数「分」存：牵动整个数据库和所有计算，两位小数四舍五入没出过问题（2026-11-08）
- `db._migrate` 每项先检查列在不在，跑几次都安全，不改成版本号（改了对真实数据库有风险、没有好处）（2026-11-08）
