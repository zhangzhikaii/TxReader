# TxReader

自己用的记账网页。目前能上传手机 App 的交易截图，自动识别交易，核对后入库并导出 CSV；手动输入、邮件导入和每月统计正在做，计划见 `docs/plan.md`。

截图识别目前支持：

| 来源 | 截图 | 说明 |
|---|---|---|
| 微信 | 「零钱明细」列表，可多张 | 时间只到分钟，秒为 `00` |
| 中国银行 | 单笔交易「明细」页，每张一笔 | 列表页没有时间，所以不支持 |
| 工商银行 | 「收支明细」列表，可多张 | 备注为「第一行, 第二行」，如 `消费, 支付宝-某商户` |
| Suica | Apple 钱包单笔交易详情页，每张一笔 | 备注为路线或店名，`→` 写作 `->`；时间只到分钟 |
| 小票 | 纸质小票 / 收据的照片，每张一笔 | 金额取「合計 / Total」那一行；备注取以「店」结尾的店名，只有分店名时前面加上 logo 文字。店名常有个别字识别错，请核对 |

识别全部在本地完成（RapidOCR），不联网。

## 运行

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
.venv/bin/python -m txreader.auth          # 输入密码，打印出密码哈希，填到 .env 的 TXREADER_PASSWORD_HASH
.venv/bin/uvicorn app:app --port 8000
```

设置都在 `.env` 里（已被 git 忽略，不要提交），各项说明见 `.env.example`。已经在系统环境变量里设置的项优先，不会被 `.env` 覆盖。

- 只在自己电脑上用、不想登录时，可以设 `TXREADER_AUTH=off`（不要在服务器上这样做）
- 登录后 2 小时没有操作会自动退出，可用 `TXREADER_IDLE_MINUTES` 改（单位分钟）；一直在用的话最长 30 天也要重新登录

打开 http://localhost:8000 ，登录后有这些页面：

- **记一笔**：顶部选添加方式
  - 截图识别：选择来源，填写账户、币种、默认种类（每个来源分别记住），拖入截图。识别出的交易进入「待核对」，修改会自动保存，下次打开还在；勾选核对好的行，点「提交入库」
  - 手动输入：一行一笔，可以连续填几笔再一起入库；时间精确到秒；日期时间、账户、币种、金额、种类都要填，描述可空；新行沿用上一行的日期、账户、币种和种类。点「入库」后会先弹出确认框；用到新的账户或币种时，确认框里会问是否新增（一个账户可以有多个币种）
  - 邮件导入：整合中
- **交易**：已入库的交易，可按添加方式和日期筛选；入库后只能改种类和描述，不能删除；截图识别的点一行查看原截图
- **导出**：勾选交易导出 CSV，默认勾选没导出过的；导出过的也能再导出，每次导出都有记录
- **结余**：选一个月，看每个账户、每个币种的月底结余（期初余额 + 起始月之后的交易），以及汇率、折算成人民币的合计、汇差盈亏、和上月比的月度差额
- **汇率**：每月手填一次「1 外币 = 多少本位币」，没填的标黄
- **设置**：账户（每个账户可以有多个币种）、币种（本位币固定为人民币）、种类的清单；拖动 ☰ 排序，可以改名（已有交易一起改），没用过的可以删除。最下面是期初余额：选起始月，填那个月底每个账户、每个币种的余额
- **登录记录**：登录成功 / 失败的记录，当前登录的设备，可以让所有设备下线。密码连续错 5 次锁定 15 分钟

### 重复的截图和交易

- 同一张截图（文件内容相同）再传不会重新识别，直接用上次的结果
- 已经入库的交易自动跳过（页面上可以展开查看）；已在待核对里的不会重复添加
- 日期和金额相同、商户不同的标为「疑似重复」，默认不勾选，确认是重复的就删掉
- 比对用的是识别出的原始值，不受你后来的修改影响；只在同一来源内比对

### 数据

都存在 `data/`（可在 `.env` 里用 `TXREADER_DATA` 改位置，已被 git 忽略）：`txreader.db` 是 SQLite 数据库，`images/` 是转成 WebP 的截图。备份这个目录即可。

## CSV 格式

`日期,曜日,账户,币种,金额,种类,描述`，例如：

```
2026/10/29 10:54:00,木,微信,人民币,-87.00,饮食费,同程旅行
```

- 微信截图只显示到分钟，秒统一为 `00`；中国银行用「交易时间」，精确到秒
- 中国银行的备注取「对方名称」，保留 `财付通-` 等支付渠道前缀
- 年份取自截图顶部的「2026年10月」；看不到时用页面上填的年份（若会落在未来则往前推一年），并标 ⚠
- 支出为负数，收入为正数；收入行以黄色底标出，记得改种类
- 多张截图的重叠部分会自动去重
- 文件带 UTF-8 BOM，Excel 直接打开不乱码

## 开发用命令

```bash
.venv/bin/python -m txreader.devtools clear              # 删除所有交易（先用英文确认，要输入 yes）
.venv/bin/python -m txreader.devtools seed oct.csv       # 导入 seed/oct.csv 里的交易
```

- 两个命令都作用在网页用的那个数据库上（`.env` 里的 `TXREADER_DATA`，默认 `data/`）
- `clear` 会删除所有交易、导出记录，以及已入库的截图识别行（这样同一张截图再传还能识别出来）；保留待核对的行、截图文件、账户 / 币种 / 种类清单、期初余额、汇率
- `seed` 的文件放在 `seed/` 文件夹（已被 git 忽略），格式同导出的 CSV：`日期,曜日,账户,币种,金额,种类,描述`。曜日会重新算，描述可以空；日期可以不带时间（`2026/10/01`、`2026-10-01 12:30`）；金额可以写成 `¥1,234.00` 或 `(¥323.08)`（括号表示负数）
- `seed` 会把文件里的账户、币种、种类都登记到清单里；只要有一行不对就整份不导入，并列出行号；如果有和库里完全一样的交易，会先问要不要继续。导入的交易算作手动输入

## 测试

```bash
.venv/bin/python -m pytest tests
```

`tests/test_api.py` 用假的识别结果和临时数据目录跑完整流程（上传、核对、入库、导出、登录），不需要截图。

> 带有个人信息的样例截图放在 `samples/<来源>/`（已被 git 忽略），例如 `samples/wechat/example.PNG` 配 `samples/wechat/example.expected.json`。测试会自动跑所有带期望结果的截图，没有样例时自动跳过。
